# Bulls and Cows - проектный дизайн (DESIGN)

## 1. Структуры данных и алгоритмы

### Структуры данных

| Тип             | Определение                         | Назначение                                                                                            |
| --------------- | ----------------------------------- | ----------------------------------------------------------------------------------------------------- |
| `Base`          | `2 \| 8 \| 10 \| 16`                | Юнион литералов поддерживаемых систем счисления; невозможная система - ошибка уже на этапе компиляции |
| `Settings`      | `{ length, base }`                  | Конфигурация раунда, выбранная на экране настроек                                                     |
| `GameStatus`    | `'playing' \| 'won'`                | Статус раунда                                                                                         |
| `GameState`     | `{ secret, base, status, history }` | Всё, что известно о раунде; длина выводится из `secret.length` (единый источник истины)               |
| `GuessEntry`    | `{ guess, bulls, cows }`            | Одна попытка вместе с её результатом                                                                  |
| `RecordEntry`   | `{ date, attempts, timeMs }`        | Один завершённый раунд в таблице рекордов                                                             |
| `RecordStorage` | `{ getItem, setItem }`              | Контракт хранилища; `window.localStorage` удовлетворяет ему структурно                                |

### Алгоритмы

**createDigitValidator (src/core/digit-validator.ts)** - каррированная фабрика: принимает систему счисления, возвращает предикат для одного символа. Допустимый алфавит - срез строки `'0123456789abcdef'`, сравнение регистронезависимое (`toLowerCase`).

**generateSecret (src/core/generate-secret.ts)** - настраивает пул всех цифр системы, затем выбирает цифры рекурсивно: каждый шаг берёт случайный индекс и иммутабельно удаляет выбранную цифру из пула (`filter`), что и гарантирует уникальность. Если пул исчерпан (length > base), функция выдает исключение.

**isValidGuess (src/core/guess.ts)** - три независимых условия: точная длина; каждый символ валиден для выбранной системы (через `createDigitValidator`); уникальность (`Set` из символов в нижнем регистре).

**evaluateGuess (src/core/guess.ts)** - нормализует регистр и раскладывает обе строки на массивы, затем: bulls = `reduce`, сравнивающий символы на одинаковых индексах; совпадения = `filter` по попытке с `includes` по секрету; cows = совпадения − bulls. Подсчёт опирается на уникальность цифр - её гарантируют `generateSecret` и `isValidGuess`, - поэтому простой проверки вхождения достаточно. Используются только map/filter/reduce, без ручных циклов.

**countPossibleSecrets (src/core/count-possible-secrets.ts)** - рекурсивный подсчёт размещений без повторений: P(length, base) = base × P(length − 1, base − 1), P(0, x) = 1, а при length > base результат 0. Результаты мемоизируются в `Map` с ключом `${length}-${base}`, поэтому повторные вызовы выполняются за O(1).

**Состояние игры (src/core/game-state.ts)** - `startGame` создаёт свежее состояние; `submitGuess` сначала проверяет guard-условия: завершённый раунд или повторная попытка возвращают тот же самый объект состояния; иначе запись добавляется и статус пересчитывается иммутабельно (`[...state.history, entry]`, `{ ...state }`).

**Рекорды (src/core/records.ts)** - `addRecord` добавляет запись, сортирует по (попытки по возрастанию, затем время по возрастанию) - сортировка `Array.sort` и оставляет топ-10 (`slice`). `loadRecords` парсит JSON: отсутствующий ключ, невалидный JSON, не-массив или записи неверной формы дают пустой массив `[]`. `saveRecords` сериализует обратно.

**UI (src/ui/)** - экраны представляют собой функции отрисовки, принимающие корневой элемент, текущие значения и колбэки (`onStart`, `onRecords`, `onNewGame`); `app.ts` соединяет их без перезагрузки страницы. Игровой экран следует паттерну «DOM - проекция состояния»: любое изменение перерисовывает весь экран из `GameState`. `filterInput` применяет `createDigitValidator` на каждое нажатие, поэтому невалидные символы физически невозможно ввести.

## 2. Анализ сложности (Big O)

| Функция                | Время                                | Память    | Обоснование           |
| ---------------------- | ------------------------------------ | --------- | --------------------- |
| `generateSecret`       | O(length × base)                     | O(base)   | см. ниже              |
| `isValidGuess`         | O(length × base) → O(length)         | O(length) | base ≤ 16 - константа |
| `evaluateGuess`        | O(n²)                                | O(n)      | см. ниже              |
| `countPossibleSecrets` | O(length) первый вызов, O(1) из кеша | O(1)      | см. ниже              |

**generateSecret - O(length × base).** Пул строится один раз за O(base). Рекурсивный `pick` выполняется `length` раз, и каждый шаг копирует оставшийся пул через `filter` (размеры base, base − 1, …), что в сумме даёт не более length × base. Конкатенация строк добавляет 1 + 2 + … + length = O(length²), но это обеспечивается работой с пулом, поскольку base ≥ length (иначе функция бросает исключение). Память: одна копия пула плюс растущая строка → O(base).

**isValidGuess - O(length × base).** `every()` проходит до `length` символов, каждая проверка сканирует алфавит не длиннее `base` символов (`includes`); `Set` строится за O(length). Поскольку base ∈ {2, 8, 10, 16} ограничен малой константой, фактически это **O(length)**.

**evaluateGuess - O(n²)**, где n - длина guess. Проход `reduce` - O(n), но `filter` по попытке вызывает `includes` по guess - линейный поиск внутри цикла, что даёт n × n сравнений. В масштабах игры (n ≤ 6) худший случай - 36 сравнений.

**countPossibleSecrets - O(length) первый вызов, O(1) повторный.** Рекурсия - цепочка из length + 1 вызовов, каждый выполняет O(1) работы (одно умножение и O(1) операции `Map`). Мемоизация делает повторные вызовы константными; размер кеша ограничен малым пространством параметров (length ≤ 6, base ≤ 16).

## 3. Принципы чистого кода

1. **Иммутабельность** - `submitGuess` (src/core/game-state.ts) ничего не мутирует: история растёт через `[...state.history, entry]`; `addRecord` (src/core/records.ts) сортирует только свою свежую копию.
2. **Внедрение зависимостей** - `generateSecret(length, base, random)` и `loadRecords`/`saveRecords(storage, …)` получают побочные эффекты как параметры, что делает ядро тестируемым без браузера; экраны получают поведение как колбэки (`onStart`, `onRecords`, `onNewGame`).
3. **DRY** - `createDigitValidator` (src/core/digit-validator.ts) - единственный источник истины «что считается валидной цифрой», переиспользуется в `isValidGuess` и `filterInput`; `collectSettings` (src/ui/settings.ts) собирает значения селектов один раз для обеих кнопок.
4. **Единая ответственность** - одна функция на файл в `src/core/`; каждый экран в `src/ui/` отвечает за одну задачу.
5. **Типобезопасность без `any`** - юнионы литералов (`Base`, `GameStatus`), `unknown` с предикатом типов (`isRecordEntry`, src/core/records.ts) и структурный контракт (`RecordStorage`), которому `window.localStorage` удовлетворяет без адаптеров.
6. **TDD** - каждая функция ядра попала в репозиторий парой коммитов: красный (`test:`), затем зелёный (`feat:`); история коммитов служит журналом разработки.
7. **DOM как проекция состояния** - src/ui/game.ts перерисовывает экран из `GameState` вместо точечной правки нод, что исключает рассинхрон интерфейса и состояния по построению.
